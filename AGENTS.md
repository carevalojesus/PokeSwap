# Flujo de trabajo de PokeSwap

El usuario ha establecido GitHub Projects como medio de organización del proyecto. Seguir [TRABAJO.md](TRABAJO.md) y consultar el [tablero](https://github.com/users/carevalojesus/projects/6/views/2) antes de iniciar tareas de implementación.

- Usar las issues existentes y respetar sus dependencias; evitar duplicados.
- Actualizar responsable y Status al iniciar, bloquear, enviar a revisión y terminar una tarea.
- Trabajar en una rama vinculada a la issue y referenciarla en la PR.
- Registrar validación real; no marcar Hecho antes de cumplir criterios e integrar los cambios.
- Verificar el estado del tablero después de cerrar issues; no asumir automatizaciones.
- Mantener README.md como definición funcional y ARQUITECTURA.md como referencia técnica.
- No ampliar alcance ni publicar cambios ajenos a la tarea solicitada. Las instrucciones explícitas del usuario tienen prioridad sobre este flujo.
